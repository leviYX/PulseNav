# PulseGeo Agent MVP Implementation Plan

**Goal:** 建立可运行、可测试的 Go Agent 与确定性空间工具调用链。

**Architecture:** Eino ReAct 调用类型化工具，HTTP 与 Agent 复用领域校验及 POI 服务。PostGIS 与演示数据通过同一接口注入，使用环境配置选择。

**Tech Stack:** Go、Eino、OpenAI-compatible API、pgx、PostGIS、net/http。

## 顺序执行

- [x] 空间算法：先在 `pkg/spatial/spatial_test.go` 覆盖距离、日期变更线、边界、非法围栏、转换，再实现 `spatial.go`；运行 `go test ./pkg/spatial`。
- [x] 领域与检索：`internal/domain` 定义领域错误、请求及 GeoJSON；`internal/poi` 编写组合查询/限额/取消测试后实现服务及演示仓储；`internal/postgres` 编写真实环境可执行的查询集成测试后实现参数化 SQL；新增 `migrations`。
- [x] Agent：在 `internal/agent` 用本地模型服务先测试工具闭环、非法工具输入、最大步骤及取消，再接入 Eino typed tools 和 ReAct。
- [x] HTTP 与启动：在 `internal/httpapi` 先测试 API 的正常输出、非法参数、错误脱敏和限流，再实现路由、请求限制和可取消的处理链；新增 `cmd/pulsegeo` 启动、环境配置和优雅退出。
- [x] 交付验证：更新 README、`.env.example` 与本地 PostGIS compose；执行 `go test -race ./...`、`go vet ./...`、`go build ./...`、`git diff --check`，运行无密钥 HTTP 冒烟测试。明确标注未运行的外部集成验证。

本轮直接在 `codex/pulsegeo-agent` 分支实现，保留既有 README 编辑，不提交或修改用户的 IDE 文件。

已完成首期实现与本地模型协议闭环、HTTP API、race 检测及真实服务进程启动/退出验证。PostGIS 集成测试已提供，并在 CI 配置真实数据库服务；本机未运行 Docker 且未配置 TEST_DATABASE_URL，因此本轮未执行真实 PostGIS 查询，不将该项视为已通过。未调用真实模型提供商。
